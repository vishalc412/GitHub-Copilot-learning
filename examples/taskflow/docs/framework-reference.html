Install on your own project

Three copies, three edits. Nothing to build, no dependency to add.

  1. Copy the framework layer

    Your application code is untouched — this only adds configuration.

    # from the repo root
cp -r examples/taskflow/.github   ~/your-project/
cp    examples/taskflow/AGENTS.md ~/your-project/
cp -r examples/taskflow/.vscode   ~/your-project/

  2. Edit exactly three files

    Keep every structure; replace only the project-specific content. copilot-instructions.md → your stack, invariants and commands. *.instructions.md → your applyTo globs and layer rules. AGENTS.md → your setup and verify commands.

  3. Open that folder as the workspace root

    Copilot resolves .github/instructions/** relative to the workspace root, so a nested .github/ is silently ignored. This is the single most common reason a correct instruction file appears to do nothing.

Four layers, most specific last

The layers are numbered because precedence is genuinely ordered: Copilot combines every file that applies to the file you are editing, and the narrower layer adds detail on top rather than repeating the broader one.

Layer 1

AGENTS.md

Tool-agnostic setup and verify contract. Read by the Copilot coding agent and other tools supporting the open agents.md standard.

Layer 2

.github/copilot-instructions.md

Repo-wide rules, read by every surface — inline completions, Chat, Agent Mode, the coding agent, and code review.

Layer 3

.github/instructions/*.instructions.md

Path-scoped via an applyTo glob — backend/**/*.java, frontend/**/*.{ts,tsx}, and test files only. Your Java rules never leak into a React file.

Layer 4

.github/chatmodes/*.chatmode.md

Active only when you select that persona. Adds task-specific constraints and a restricted toolset on top of the standing rules.

They are additive, not exclusive. The fix for a contradiction between layers is to write instructions that do not fight — not to memorise an override rule.

Prompt library

Four reusable commands in .github/prompts/. Type the slash command in Copilot Chat; each one asks for what it still needs, then works in the order that actually holds together.

/new-endpoint
DTO → service → exception + handler → controller → tests → the TypeScript type mirror. Then runs mvn test and reports the real count.
/new-component
Types → API function → hook → presentational component → wiring → Vitest suite. Enforces no fetch inside a component.
/add-tests
Reports existing coverage and the gaps before writing, picks the cheapest level that proves each one, and never edits production code.
/review-diff
Correctness → layer violations → contract drift → version traps → test gaps → style, stopping at the first category with real findings.

Three personas, scoped by capability

The most reliable way to stop an agent doing something you did not want is to give it less capability than the task allows. Each mode declares its own toolset.

Architect

Locates the change, checks the contract, weighs two or three options, emits a numbered plan with a definition of done.

Reviewer

Reviews a diff in risk order and caps at the top five findings. Says a clean diff is clean instead of inventing work.

Test writer

Version traps the instructions encode

Every row below was hit and fixed while building and running this project — not collected from release notes. This is the class of knowledge a model reliably guesses wrong, which makes it the most valuable thing an instruction file can hold.

What you seeThe rule
package org.springframework.boot.test.autoconfigure.web.servlet does not exist Boot 4 split the test slices out. @WebMvcTest needs spring-boot-starter-webmvc-test and now lives in boot.webmvc.test.autoconfigure; @DataJpaTest needs spring-boot-starter-data-jpa-test under boot.data.jpa.test.autoconfigure.
No qualifying bean of type 'com.fasterxml.jackson.databind.ObjectMapper' Boot 4 ships Jackson 3 under tools.jackson. There is no com.fasterxml mapper bean. Use JSON string literals in web tests — they assert the real wire format anyway.
jpaAuditingHandler → JPA metamodel must not be empty Keep @EnableJpaAuditing in its own @Configuration, never on the application class — the web slice loads that class but excludes JPA, so every @WebMvcTest dies. Slice tests that need auditing @Import it explicitly.
A mistyped URL returns 500 A blanket @ExceptionHandler(Exception.class) swallows Spring's NoResourceFoundException. Any catch-all needs an explicit NoResourceFoundException → 404 companion, plus a regression test.
@MockBean cannot be resolved Removed in Boot 4. Use @MockitoBean from org.springframework.test.context.bean.override.mockito.
/h2-console → No static resource h2-console The console moved to its own module. spring.h2.console.enabled alone does nothing without the spring-boot-h2console dependency — and nothing warns you.
'test' does not exist in type 'UserConfigExport' Import defineConfig from vitest/config, not vite. Everything else typechecks first, so the error arrives late and reads unrelated.

Small, layered, and genuinely running — it exists so the rules above point at real code rather than describing an idea. No database server, no Docker, no credentials.

  • Lifecycle rules defined once on an enum, exposed to the client as allowedTransitions — the UI cannot offer an illegal move

  • RFC 9457 problem+json errors, verified live: 201+Location, 400 field errors, 409 illegal transition, 409 duplicate title, 404 unknown path
